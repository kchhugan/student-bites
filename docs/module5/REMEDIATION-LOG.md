# Student Bites — Module 5 remediation log

Baseline: the actual Module 4 final submission (`Student_Bites_Module4_Final_Submission.zip`). Date of review: 2026-11-22. These are code-review findings; **not** claims that an automated WCAG tool detected them. Retests were conducted against the edited HTML/CSS using a Chromium browser-assisted check and the included automated structural checker. Each item has a specific fix and a repeatable retest.

| ID | Issue / baseline evidence | Impact | Priority | Fix applied | Retest / result |
|---|---|---|---|---|---|
| M5-01 | `recipe.html` had a generic document title, `Student Bites \| Recipe Detail`, despite showing One-Pan Veggie Pasta. | Browser tab and screen-reader document navigation did not identify the recipe. | High | Changed title to `Student Bites \| One-Pan Veggie Pasta`. | Parsed revised title; automated page-title audit reports no missing titles. **Pass.** |
| M5-02 | Homepage card `<a>` contained a descriptive `<img alt>` followed by a heading naming the dish. Its computed link name could read both the photo description and recipe name, making the link unnecessarily long. | Verbose and potentially repetitive screen-reader link announcement. | Medium | Changed card image `alt` to `""`, retaining meaningful visible `<h3>` inside each link; the same image on its separate recipe page retains informative alt text. | Inspected all three revised card links and image alt attributes; the static audit finds no unnamed anchors. **Pass (DOM-based); full screen-reader announcement not verified.** |
| M5-03 | Recipe detail pages did not identify the current recipe in a page-level breadcrumb; top nav only pointed to home categories and Tips. | Less context for readers entering a detail page directly or navigating via landmarks. | Medium | Added native `<nav aria-label="Breadcrumb">` with `All recipes` link and current recipe text bearing `aria-current="page"` to four detail pages. | Chromium browser inspection of pasta breadcrumb returns `All recipes / One-Pan Veggie Pasta`; current item found. Other pages passed structural audit. **Pass.** |
| M5-04 | Original navigation CSS used small `.79rem` type with vertical padding `.45rem`, producing small targets for many users. | More difficult touch/pointer operation. | Medium | Added `min-block-size: 2.75rem` (44px at 16px root) and flex alignment. | Browser reflow run shows no horizontal overflow at 320/402/744/1440px on any of six pages, including expanded navigation. **Pass for tested viewports; not a complete pointer-device study.** |
| M5-05 | Skip link targeted `<main id="main">` without a `tabindex`, leaving focus transfer less explicit across user agents. | Potential uncertainty when moving keyboard focus from skip link to content region. | Medium | Added `tabindex="-1"` to every `<main id="main">`; did not add the main region to normal Tab sequence. | In Chromium, first Tab focused `Skip to main content`; Enter then moved active focus to `main`. **Pass.** |
| M5-06 | Tips summaries had a general global focus style but no local focus style considering the disclosure's pale background and border. | Focus could be harder to locate within the grid of expandable panels. | Medium | Added explicit 3px focus outline to `.tip-disclosure summary:focus-visible` and 44px minimum height. | Chromium focus style = `solid`; Enter opened and closed the first disclosure; Tab moved to another `SUMMARY`, showing no trap in this sampled path. **Pass.** |
| M5-07 | Three recipe previews reused a generic pasta-oriented description (`A sample Student Bites recipe detail page...`). | Less descriptive search/browser previews, especially when sharing a page link. | Low | Replaced descriptions with page-specific recipe-preview descriptions, clearly indicating unverified content. | Inspected page-specific description strings and ran document audit for each page. **Pass.** |

## Reproduction steps

1. Extract the Module 4 baseline ZIP and the Module 5 ZIP into separate folders; compare `recipe.html` `<title>`, homepage card image `alt`, detail breadcrumbs, `<main>` attributes, preview descriptions and `css/styles.css` navigation and summary rules.
2. Open `index.html`, press Tab once then Enter: the main region should receive focus. Use keyboard-only Tab/Shift+Tab to inspect the navigation links.
3. On `tips.html`, Tab to `Grocery shopping`, use Enter/Space to open and close it, and Tab to the next disclosure; observe focus outline. Repeat on all three disclosures on a real browser for final release.
4. Run `python tools/check_accessibility.py` from the extracted project root to reproduce structural audit findings.
5. See `browser-checks.json`, `automated-structural-audit.json`, `accessibility-tree-sample.json` and screenshots in this folder for the evidence actually captured.
